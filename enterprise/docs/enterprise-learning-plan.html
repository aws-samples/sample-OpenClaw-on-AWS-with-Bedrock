OPENCLAW ENTERPRISE · 从初学者到可独立搭建

学习、理解与完整搭建路线图

适合具备初级 AWS 操作经验和基础 Python 能力的学习者。目标不是背代码，而是能在隔离测试环境中部署、配置、排障、升级并安全扩展本项目。

建议节奏：12 周，每周 6–10 小时。每周都要完成一个“可验证产物”，而不是只看文档。生产部署有成本和数据风险，请先使用独立 AWS 账号、最小权限 IAM 用户、测试 Stack 名称和预算告警。

1. 做到“完整搭建”相当于什么水平？

能够独立完成

使用版本化镜像 tag 部署基础设施、管理后台、Gateway、AgentCore Runtime 和 Always-On ECS；配置员工、岗位、Skill、SSM Key、IM 与权限；定位大多数配置、运行时和数据链路问题。

能力定位

接近初中级云端 AI 应用工程师 / 平台工程师：具备全栈集成、容器化部署、AWS 托管服务、Agent Runtime 和基础运维能力。

不等于

不等于资深云架构师或安全负责人。生产多账号治理、合规审计、高可用设计、灾备、成本优化与事故响应仍需要更深实践和评审。

如果你还能独立评估权限边界、失败回滚、监控告警、成本预算，并能安全改造运行时或基础设施代码，就已接近中级 AI 平台工程师的实践能力。

3. 关键概念：先学业务，再学技术

组织关系

Department
  └── Position.defaultSkills
        └── Employee.personalSkills
              └── Agent

岗位提供默认 Skill，员工可额外获得个人 Skill；运行时再根据身份过滤，不能只信任前端显示。

三种存储

DynamoDB 存业务记录。
S3 存文件型内容。
SSM SecureString 存密钥与 Token。

两种运行方式

Serverless：按需、成本较低、约 5 分钟空闲后可能回收。
Always-On：ECS 常驻、EFS 持久化、适合实时 IM。

4. 学习前准备：安全实验环境

不要把第一个实验直接放到生产账号。本项目会创建网络、EC2、ECS、EFS、ECR、S3、DynamoDB 等资源，也会产生 Bedrock、存储、网络和计算费用。创建、更新或删除 Stack 前都要确认目标账号、区域和 Stack 名称。
  1. 准备独立 AWS Sandbox 账号或至少独立测试环境，区域建议固定一个。
  2. 创建个人 IAM 身份，启用 MFA；不要使用 root 账号日常部署。
  3. 设置 AWS Budgets / Cost Explorer 告警，先设低阈值。
  4. 本地安装：Git、Python 3.12、Node.js 24、AWS CLI v2；Docker 可先不装，本项目在 EC2 上构建 ARM64 镜像。
  5. 只从 enterprise/.env.example 创建自己的 .env；不要提交它，不要把 Key、JWT、Token 贴进文档、Issue 或聊天。

6. 完整搭建的推荐里程碑

里程碑 A：本地理解，不部署
  1. 阅读本页第 1–5 周指定文件。
  2. 打开 enterprise/docs/ui-guide.html，将界面与 API、数据模型对应起来。
  3. 完成三张图：业务关系图、一次消息流图、Skill Key 流图。
里程碑 B：测试环境基础设施
  1. 检查 AWS 身份、区域、预算、服务配额和模型访问。
  2. 从 .env.example 创建测试配置，使用未被占用的 Stack 名称。
  3. 先运行候选镜像构建：bash enterprise/deploy.sh --build-only。
  4. 再执行完整部署；遇到 CloudFormation 失败先查 CREATE_FAILED 事件，不要直接删除资源或 Stack。
里程碑 C：功能验收
  1. 管理员登录，检查组织、岗位、员工、Agent、Skill Catalog。
  2. 确认员工有 Agent 与 Skill 授权。
  3. 配置一个测试 Skill Key 到 SSM，验证运行时只检查变量存在，不输出值。
  4. 完成一轮员工对话，检查 Usage 与 Skill Calls 是否出现记录。
  5. 验证 Manager 只能看到本部门及下级部门数据。
里程碑 D：升级与可恢复性
  1. 修改一个无风险前端文案或测试 Skill 的描述。
  2. 设置一个全新的版本化 IMAGE_TAG，不要覆盖稳定 tag。
  3. 先 --build-only，确认 smoke test，再用 --skip-build --skip-seed 更新。
  4. 验证 Admin Console、Gateway、Serverless Runtime、Always-On 服务均指向预期版本。

7. 必须能讲清楚的三条链路

A. 员工消息 → 模型回复

IM / Portal
→ Gateway / Tenant Router
→ employeeId 映射
→ AgentCore 或 ECS
→ server.py
→ workspace_assembler.py（首次）
→ OpenClaw Gateway
→ Bedrock 模型
→ Guardrail / Usage / Memory
→ 用户

B. 管理员配置 Skill Key → Skill 可用

Admin Console
→ PUT /skills/keys/{skill}/{env}
→ SSM SecureString
→ 受影响 Session / ECS service 刷新
→ skill_loader.py 根据员工授权读取
→ 仅注入允许的环境变量
→ Gateway 使用该环境运行 Skill

C. Skill 调用 → Usage 页面

Agent 实际应用 Skill
→ 当前请求回执（主信号）
→ server.py 严格校验并移除 marker
→ DynamoDB SKILL_USAGE#date#skill#employee#mode
→ FastAPI /usage/by-skill 与 /usage/skill/{id}/users
→ React Usage 页面显示 Calls 与用户下钻

9. 学习时的调试方法

前端问题

浏览器 Network → API 状态码 → FastAPI 路由 → DynamoDB/S3 记录。先确定数据在哪一层丢失。

Agent 不回复

检查 Runtime / ECS 是否可达 → Gateway 是否 ready → OpenClaw provider → Bedrock 模型访问 → IAM 权限。不要打印原始用户消息或密钥。

Skill 无法调用

检查授权记录 → S3 manifest → SSM 参数是否存在 → 环境变量是否注入。只检查变量名和存在性，绝不显示值。

部署失败

先查 CloudFormation 的第一个 CREATE_FAILED 资源。区分 IAM、配额、区域模型、网络、名称冲突和镜像构建失败。

10. 安全与运维底线

  • 绝不提交或输出：API Key、JWT Secret、Gateway Token、内部 Service Token、用户聊天内容。
  • Skill Key 必须是 SSM SecureString；不要放进 SKILL.md、Git、浏览器返回值或日志。
  • 生产更新使用新的版本化 ECR tag；先构建和 smoke test，再切 Runtime。
  • 先查事件再处理失败 Stack；删除 Stack、S3、DynamoDB、EFS 前必须确认数据保留策略。
  • 最小权限、MFA、预算告警、测试与生产账号隔离是搭建能力的一部分。

11. 最终毕业项目

在测试环境完成“一个受控动态 Skill”

  1. 创建一个不依赖真实第三方 Key 的 Skill，包含 skill.json 与 SKILL.md。
  2. 上传或通过项目已有流程让它出现在 S3 Skill Catalog。
  3. 将它分配给一个岗位，再给一个员工授予个人 Skill，解释两者差异。
  4. 从员工 Portal 或 IM 发起一次任务，确认 Agent 有该 Skill。
  5. 在 Usage 页面看到该员工的 Skill Calls；打开 Users 查看按用户统计。
  6. 做一个小改动，使用新的 image tag 构建、验证、更新测试 Stack。
  7. 写一页自己的运行手册：部署步骤、验证点、常见失败与回滚方案。

完成后，你已经不仅会“使用 AI Agent”，而是能搭建和维护一个多租户企业 Agent 平台的完整基础闭环。
